# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Goal

This repository is a **full infrastructure-as-code, iterable Google Cloud training lab**. The intent is that any learner can clone this repo, run a single command, and get a fully provisioned GCP environment to practice against — then tear it down just as easily. Labs must be modular, repeatable, and cost-conscious.

## Project Structure

The lab chain uses **two** GCP projects. All resources across all labs share one `deployment_uid` (generated by lab-01 on first apply).

| Project naming | Labs that deploy into it |
|----------------|--------------------------|
| `[uid]-deployments-palu` | `lab-01-gsc-privesc` |
| `[uid]-webapp-palu` | `lab-01-gsc-privesc-b`, `lab-02-kms-privesc` |

`lab-01-gsc-privesc` generates `random_id.deployment` and exposes it as output `deployment_uid`. All subsequent labs receive `deployment_uid` as an input variable — they never generate their own.

## Common Commands

### Deploy the full lab chain
```bash
./scripts/deploy-chain.sh apply
./scripts/deploy-chain.sh destroy
```

### Deploy a single lab
```bash
./scripts/lab.sh apply   lab-01-gsc-privesc
./scripts/lab.sh destroy lab-01-gsc-privesc
```

See [`docs/deployment.md`](docs/deployment.md) for prerequisites, project setup, per-lab tfvars, and troubleshooting.

### Lint & format
```bash
terraform fmt -recursive
tflint --recursive
```

### Generate module docs
```bash
terraform-docs markdown . > README.md   # run inside a module directory
```

## IaC Conventions

- **Every lab** must have: `main.tf`, `variables.tf`, `outputs.tf`, `backend.tf`, `providers.tf`, `README.md`.
- **Every module** must expose a `README.md` generated by `terraform-docs`.
- Variable names use `snake_case`. Resource names use hyphens in GCP, underscores in Terraform identifiers.
- All resources must carry at minimum these labels: `env`, `lab`, `owner`.
- Use `lifecycle { prevent_destroy = false }` explicitly in lab roots so teardown is never blocked.
- Locals block at the top of `main.tf` for computed names/labels — no string interpolation scattered through resource blocks.
- Remote state: GCS backend per lab (`backend "gcs" {}`). Bucket name is injected by `lab.sh` via `-backend-config`, never hardcoded.
- `deployment_uid`: only `lab-01-gsc-privesc` generates it (`random_id.deployment`). All other labs declare `variable "deployment_uid"` and receive it as input. This ensures all resource names across all labs share the same prefix.
- `project_id`: each lab declares `variable "project_id"`. The root `terraform.tfvars` sets it to the deployments project. Labs that target the webapp project receive it via `-var project_id=...` from `deploy-chain.sh` or via a per-lab `terraform.tfvars`.

## Cost Controls

- Default machine types: `e2-small` unless the lab explicitly requires more.
- Disks: standard persistent (`pd-standard`).
- Cloud SQL: `db-f1-micro`. Always set `backup_configuration { enabled = false }` and `deletion_protection = false`.
- Always wire up `terraform destroy` as the cleanup step.
- See `docs/cost-controls.md` for per-service guidance.

## Lab Tracker

**Canonical source of truth:** [`docs/labs/README.md`](docs/labs/README.md)

That file tracks every lab with a three-state status:
- `[ ]` not started
- `[~]` in progress / under construction — Claude may set this
- `[x]` done — **only the repo owner may set this**

Always update `docs/labs/README.md` when starting, modifying, or completing a lab or any stage within one. Never mark a step `[x]` autonomously.

## Lab Types

Labs may be **infrastructure labs** (learner builds something) or **security/CTF labs** (learner attacks a pre-deployed environment).

Security labs deploy a vulnerable-by-design environment. The `README.md` for each security lab describes the attacker's starting position and the intended kill chain.

## Adding a New Lab

1. Create `labs/lab-XX-short-name/` with `main.tf`, `variables.tf`, `outputs.tf`, `backend.tf`, `providers.tf`, `README.md`.
2. If the lab targets the webapp project, add `variable "deployment_uid"` and `variable "project_id"` (no default) — it will receive them from `deploy-chain.sh`.
3. Write the scenario in `README.md`.
4. Add an entry to `docs/labs/README.md`.
5. Add the lab's apply/destroy steps to `scripts/deploy-chain.sh`.
6. Run `terraform validate` and `tflint` before committing.
