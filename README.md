# Google Cloud Training Lab

A collection of hands-on, infrastructure-as-code GCP labs. Each lab deploys a real cloud environment to practice against and can be torn down in a single command when you are done.

---

## What is this?

This repo provides self-contained GCP environments for learning cloud security. Each lab folder under `labs/` is a standalone Terraform root that provisions a realistic, intentionally vulnerable GCP setup. Labs form a continuous kill chain — the credential you steal in one lab opens the door to the next.

| Lab folder | Project | Title | Type |
|------------|---------|-------|------|
| `lab-01-gsc-privesc` | `[uid]-deployments-palu` | GCP Privilege Escalation via Stolen SA Key | Security / CTF |
| `lab-01-gsc-privesc-b` | `[uid]-webapp-palu` | Cloud Function bridge — flag endpoint + RCE surface | Security / CTF |
| `lab-02-kms-privesc` | `[uid]-webapp-palu` | KMS Privilege Escalation via Metadata Token | Security / CTF |

Full lab status and build progress: [`docs/labs/README.md`](docs/labs/README.md)

### GCP projects and permissions

The lab chain requires **two separate GCP projects**. Cross-project privilege escalation is the learning objective, so a single project will not work.

Projects follow the naming convention `[uid]-<name>-palu` where `[uid]` is a shared random identifier generated by the first `terraform apply` of lab-01.

| Project | Used by | Purpose |
|---------|---------|---------|
| `[uid]-deployments-palu` | `lab-01-gsc-privesc` | Deployments project — bucket, compute, Cloud SQL |
| `[uid]-webapp-palu` | `lab-01-gsc-privesc-b` + `lab-02-kms-privesc` | Webapp project — Cloud Function, KMS, Secret Manager, BigQuery |

Your deploying identity (user account or CI service account) needs the following roles **on both projects**:

| Role | Why it is needed |
|------|----------------|
| `roles/editor` | Create compute, storage, SQL, IAM, Cloud Function, KMS, BigQuery resources |
| `roles/storage.admin` | Create and write the remote-state GCS bucket |
| `roles/iam.serviceAccountAdmin` | Create per-lab service accounts |
| `roles/iam.securityAdmin` | Bind IAM policies and create custom roles |
| `roles/cloudkms.admin` | Create KMS key rings and keys (Project C only) |
| `roles/secretmanager.admin` | Create Secret Manager secrets (Project C only) |

## Quickstart

### 1 — Authenticate

```bash
gcloud auth application-default login
```

### 2 — Bootstrap projects and variables (once)

**Bash (Linux / macOS / WSL)**
```bash
./scripts/setup.sh --billing-account=XXXXXX-XXXXXX-XXXXXX
```

**PowerShell (Windows)**
```powershell
.\scripts\setup.ps1 -BillingAccount XXXXXX-XXXXXX-XXXXXX
```

`setup` creates the three GCP projects, links billing, enables required APIs, creates the Terraform state bucket, and writes `terraform.tfvars` in one shot. Find your billing account ID with `gcloud billing accounts list`.

### 3 — Deploy

**Bash**
```bash
./scripts/deploy-chain.sh apply
```

**PowerShell**
```powershell
.\scripts\deploy-chain.ps1 apply
```

The deploy-chain script runs all five steps automatically — it captures outputs from each lab and passes them to the next as `-var` flags. No manual tfvars editing is needed between steps.

On completion it prints the deployment UID, Cloud Function URL, and the command to generate the learner's starting SA key. An auto-destroy timer fires after 2 hours.

### 4 — Tear down

**Bash**
```bash
./scripts/deploy-chain.sh destroy
```

**PowerShell**
```powershell
.\scripts\deploy-chain.ps1 destroy
```

Destroys all labs in reverse order.

## Lab types

**Security / CTF labs** deploy a vulnerable-by-design environment. The learner starts with a single stolen credential and must follow the kill chain to reach the final flag. Each lab ends with a pivot that becomes the entry point for the next lab.

---

## Cost

All labs use the smallest viable machine types (`e2-small`) and cheapest Cloud SQL tier (`db-f1-micro`). Estimated combined cost while all three projects are running is under **$3/day**.

**Always run `destroy` when done with a session** — Cloud SQL and compute instances accrue cost even when idle.

See [`docs/cost-controls.md`](docs/cost-controls.md) for per-service estimates.
